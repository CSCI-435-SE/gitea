## Question 2: What is ont thing you learned about the codebase or about software engineering practice?
The backend changes for the first medium sized issue I implemented really showacased the extent to which the code has been fragmented and responsibility spread everywhere. Previous to the implementation, every implementation of a shortcut had to be specifically defined at every location that it wanted to be used. Thus, there was no way to cleanly monitor clashes, the same shortcut keys kept getting implemented over and over in different places, and no central location to register or monitor the behavior of shortcuts. After the implementation, there is finally a central location through where the behavior is established and processed.

When it comes to the concept of software engineering itself, the use of AI really forced me to reckon with what is needed and what is not. Issue splitting and ACs were too specific / complicated, and feature implementations added more changes that were needed. Controlling AI meant me unknowingly following the YAGNI ("You aren't gonna need it", part of extreme programming) concept to direct the AI agent to implement features to the defined extent, reduce side-effecting behavior, and be realistic on requirements and the end goals of an issue.
